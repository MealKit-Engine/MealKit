# MealKit 엔진 로드맵

엔진에 넣을 기능과 순서. 게임 프로젝트(`D:\GameEngine\MealKit\<게임>`)에서 필요한 것을 기준으로 정했다.
끝낸 항목은 `[x]`로 표시하고, 순서가 바뀌면 이 문서를 고친다.

## 판단 기준

모든 기능은 아래 순서로 따져서 넣을지 정한다.

1. **3D + 멀티플레이를 해치지 않는가.** 시뮬레이션에 닿는 기능은 락스텝 결정론(README "결정론 규칙")을 지켜야 한다.
2. **가벼움과 속도.** 목표 하드웨어는 Intel 내장 그래픽 사무용 PC, **최소 사양은 Intel 11세대(Xe 내장 그래픽) 이상**이다. 아래 예산을 넘는 기능은 끌 수 있어야 한다.
3. **DX12만 쓴다.** RHI 추상화와 다른 API 백엔드는 만들지 않는다.
4. **외부 라이브러리는 꼭 필요할 때만.** Windows에 기본으로 있는 API(XAudio2, XInput 등)를 먼저 쓰고, 그다음 파일 하나짜리 라이브러리를 고른다.

### 성능 예산 (최소 사양 Intel 11세대 Xe 내장 그래픽, 1280×720, 60 fps 기준)

"현재" 값은 최소 사양보다 빠른 Core Ultra 5 125U(Xe-LPG)에서 잰 것이다. 최소 사양 실기에서 다시 재야 한다.

| 항목 | 예산 | 현재 |
|---|---|---|
| 프레임 전체 (GPU) | 8 ms 이하 (60 fps에서 절반을 여유로 남김) | 약 0.3 ms |
| 시뮬레이션 틱 (30 Hz) | 틱당 4 ms 이하 | 0.9~2.5 ms (바디 2,000개) |
| 드로우 콜 | 200회 이하 | 4회 |
| 네트워크 (4인, 호스트 송신) | 10 KB/s 이하 | 약 5 KB/s |
| 게임 실행 파일 | 5 MB 이하 (에셋 제외) | 약 1.4 MB |

## 현재 있는 것 (v0.3)

DX12 포워드 렌더러(인스턴싱, 정점 색), Jolt 물리(결정론), 입력만 보내는 락스텝(UDP/Steam), glTF 모델 + LOD,
`.scene` 씬, 내장 에디터(기즈모, 되돌리기, 플레이 모드, 출시 빌드), Tracy 프로파일링, 프로젝트 템플릿.

**없는 것 중 게임을 만들 때 바로 막히는 것**: 소리, 화면 글자(HUD·메뉴), 게임패드, 텍스처, 중간 참가.

**툴로서 불편한 점**: 게임이 에디터에 자기 오브젝트 종류를 추가할 수 없다(`EntityKind`가 엔진에 고정). 튜닝 값이 코드 상수라 숫자 하나에도 빌드가 필요하다.
코드를 고치면 에디터를 닫아야 빌드된다. 상태 하나를 추가하면 구조체·`step`·`hash`·그리기 네 곳을 고쳐야 하고, `hash`를 빠뜨려도 에러가 나지 않는다.

## 0단계 (v0.4): 개발자 경험

기능을 더 쌓기 전에 툴부터 편하게 만든다. 툴이 불편한 채로 기능을 쌓으면 나중에 그 기능들을 다시 고쳐야 한다.
원칙: **무엇을 어디에, 얼마나는 에디터(데이터)에서, 어떻게 동작하는지는 코드에서** 다룬다. 비주얼 스크립팅은 만들지 않는다.

### [x] 고도식 범용 에디터 + 게임 DLL 핫 리로드 (결정·완료 2026-10-15)
- **구현됨**: `MealKitEditor.exe` + `mealkit.dll`(Editor 빌드, RelWithDebInfo, 동적 CRT), 프로젝트 관리자(최근 목록, 폴더 열기, 새 프로젝트),
  `mealkit.project`, `<이름>_game.dll`(게임 코드만, 다시 빌드 수 초), 원본 DLL 감시 핫 리로드, `Ctrl+R` 게임 코드 빌드, 빌드 실패 시 이전 DLL 유지,
  엔진이 더 새것이면 열 때 자동 빌드, `GameInstance` API 버전 검사. 출시 exe는 그대로(결정론 해시 동일 확인).
- **남은 것**: 디버거가 붙어 있으면 PDB가 잠겨 핫 리로드 빌드가 실패할 수 있다(PDB 이름을 빌드마다 바꾸는 방식 검토).
  mealkit.dll을 다시 빌드할 때는 에디터를 닫아야 한다. 디버그 CRT용 에디터 구성(EditorDebug)은 아직 없다.
- **왜**: 지금은 프로젝트마다 에디터 exe가 따로 있고 게임 코드가 그 안에 들어 있어서, 코드를 고치면 에디터를 닫고 빌드하고 다시 열어야 한다. 에디터와 VS Code를 같이 띄워 놓고 일할 수 없다.
- **구조**:
  - 엔진 저장소가 **에디터 하나**(`MealKitEditor.exe`)를 만든다. 실행하면 **프로젝트 관리자**(최근 프로젝트, 열기, 새 프로젝트)가 뜨고, 프로젝트 폴더를 연다.
  - 프로젝트는 에디터용으로 **게임 DLL**(`<이름>_game.dll`: World, GameSession)만 빌드한다. 에디터가 이 DLL을 불러 플레이 모드를 돌린다.
  - VS Code에서 DLL만 다시 빌드하면 에디터가 편집 모드에서 바꿔 끼운다(씬·카메라·선택 유지). 컴파일 에러는 에디터 로그 창에도 표시.
  - **출시용 `<이름>.exe`는 지금처럼 정적 단일 exe** (가벼움, 결정론 영향 없음).
- **설계 결정할 것**:
  - 에디터와 게임 DLL이 엔진을 같이 써야 하므로(`PhysicsWorld`, `ModelCache` 등), 에디터 구성에서는 엔진도 DLL(`mealkit.dll`)로 만들고 CRT는 동적(`/MD`)으로 쓴다. 출시 구성은 정적 그대로.
  - 게임 DLL 진입점은 C 함수 하나(`mealkitGameCreate`)와 **API 버전 번호**. 엔진과 DLL 버전이 다르면 불러오지 않고 다시 빌드하라고 알린다(크래시 대신).
  - 에디터 플레이와 출시본이 네트워크로 섞이지 않도록 콘텐츠 해시에 빌드 구성을 포함한다.
- **Dev 빌드 구성**: 최적화는 켜고 링크 시간 최적화(LTCG)는 끈 구성. 게임 DLL 다시 빌드를 수 초로 줄인다.
- **영향**: `new_project.ps1`, 프로젝트 템플릿, `mealkit_add_game()`, 에디터 [빌드] 메뉴(프로젝트 경로를 실행 중에 알게 됨)가 바뀐다. 프로젝트의 `editor.bat`은 엔진 에디터에 프로젝트 경로를 넘기는 역할만 남는다.
- **단점(감수)**: DLL 경계 관리, 엔진·DLL 버전 불일치 처리, 디버깅 설정이 조금 복잡해진다.

### [x] 게임 코드 구조: `sim/` · `view/` 폴더와 결정론 검사 (완료 2026-10-15)
- **구현됨**: 예제·템플릿 코드를 `sim/`(World: 상태·`step` 순서·`hash`, `Systems.h`, `Players.cpp`, `Props.cpp`), `view/`(Camera, LocalInput, Draw), `app/`(GameSession, main, GameModule)로 나눴다.
  `World::step()`은 시스템 함수를 순서대로 직접 부르고, 시스템 함수는 `World&`만 받는다(이번 틱 입력은 `world.inputs`). 상자 색은 sim에서 팔레트 번호만 갖고 색은 `view/`가 정한다.
  구조를 바꾼 뒤에도 같은 시드·입력의 상태 해시가 이전과 같다(`mp_test` PASS).
- **검사**: `engine/tools/SimCheck.cpp`(`mealkit_simcheck`)가 `sim/` 파일을 토큰 단위로 검사한다(주석·문자열 제외). `mealkit_add_game()`이 게임 타깃보다 먼저 실행하고,
  어기면 `파일(줄,열): error SIMnnn`과 대신 쓸 것을 출력하고 빌드를 멈춘다(VS Code `$msCompile`이 잡는다). 게임 프로젝트의 Editor 빌드는 `MealKitTargets.cmake`로 이 도구를 가져온다.
  막는 것: CRT 수학 함수(호출), `quatFromAxisAngle`, `rand`·`<random>`, 실제 시간(`<chrono>`, `time()`, `nowSeconds`), `new`/`delete`/스마트 포인터,
  `virtual`/`override`, 코루틴·스레드·`atomic`, `unordered_*`, 가변 `static`·전역 변수·`thread_local`, `using namespace std`, 렌더러·플랫폼·에디터·`game/`·`view/`·`app/` 헤더.
- **CMake**: `mealkit_add_game(<이름> [SOURCE_DIR source])`이 `sim/ view/ app/`을 `GLOB_RECURSE CONFIGURE_DEPENDS`로 모은다. 예전 방식(`SOURCES` 나열)도 그대로 받는다(이때 `sim/` 폴더가 없으면 검사도 없다).
- **남은 것**: 설정 헤더는 설정 시스템(1단계)이 생기면 금지 목록에 넣는다. 매크로 안에 숨긴 금지 코드와 함수 포인터로 넘긴 수학 함수는 잡지 못한다(그림자 시뮬레이션·`mp_test`가 마지막 확인).
  이미 만든 프로젝트는 자동으로 옮겨지지 않는다(프로젝트 업그레이드 도구 항목).

### [x] 기본 도구: `Pool<T>` · 틱 이벤트 · 틱 타이머 · `GameContext` (완료 2026-10-15)
- **구현됨**: `mealkit/sim/Pool.h`(`Id<T>` 세대 번호, `for (auto [id, item] : pool)` 슬롯 순서 순회, `endTick(onDestroy)`, `hashState`),
  `mealkit/sim/TickEvents.h`, `mealkit/sim/TickTimer.h`, `mealkit/game/GameContext.h`(창·렌더러·에셋·세션 + 뷰포트·입력 허용, `kApiVersion` 2).
  `MEALKIT_ASSERT`는 Editor 빌드에서도 켜진다(`MEALKIT_ASSERTS`, 디버거가 없으면 로그만). sandbox의 상자는 `Pool<Prop>`(바디 id를 항목에 둔다),
  밀치기 쿨다운은 `TickTimer`, 밀치기는 틱 이벤트 → 화면 충격파(`view/Effects`). SimCheck 안내 문구가 이 도구들을 가리킨다.
- **결과**: 상태 해시에 Pool 슬롯 상태가 들어가 해시 값 자체는 이전과 다르다(`mp_test` 3+1 피어 900틱 PASS). Pool 용량은 튜닝 시스템 전까지 `World::reset` 인자.
- **남은 것**: sandbox는 상자를 지우지 않아 삭제 경로는 단위 테스트로만 확인했다(실제 게임 코드에서 처음 쓸 때 `mp_test`로 다시 확인).
  이미 만든 프로젝트(`D:\GameEngine\MealKit\Sandbox`)는 옛 `GameInstance` 시그니처라, 새 엔진으로는 게임 코드 빌드가 실패한다(에디터에서 플레이 불가). 손으로 옮기거나 업그레이드 도구로 처리한다.
- **왜**: `docs/CODING_MODEL.md`의 "한 문제에 한 답"은 엔진이 그 답에 쓸 도구를 줘야 지켜진다. 도구가 없으면 프로젝트마다 다시 만들고 모양이 갈린다.
- **방식**: `mealkit/sim/`에 `Pool<T>`(매치 시작 때 정하는 고정 용량, 세대 번호 id, 즉시 생성·틱 끝 일괄 삭제, 만든 틱에는 순회 제외),
  시뮬레이션 → 화면 전용 틱 이벤트 배열, 틱 타이머(`readyTick`) 헬퍼. 화면 쪽은 엔진 서비스(렌더러·입력·소리·에셋·UI·디버그 UI)를 묶은 `GameContext&` 하나를 `GameInstance`에 넘긴다(`kApiVersion` 올림).
  `GameSession`은 `step()`마다 틱 이벤트를 화면 쪽 큐로 옮긴다(한 프레임에 여러 틱이 돌 때 빠지지 않게). `MEALKIT_ASSERT`를 Editor 빌드에서도 켠다.
- **순서**: 오브젝트 타입 시스템과 상태 필드 선언이 이 도구 위에 놓이므로 그보다 먼저 한다.
- **결정론**: Pool 순회는 슬롯 순서. Pool 상태(세대 번호, 빈 슬롯 목록 포함)는 `hash()`에. 틱 이벤트는 시뮬레이션이 읽지 않으므로 해시에 넣지 않는다.

### [x] 게임 정의 오브젝트 타입 + 인스펙터 필드 (완료 2026-10-15)
- **구현됨**: 필드 선언 장치 `mealkit/core/Reflect.h`(`MEALKIT_STRUCT`/`MEALKIT_OBJECT`/`MEALKIT_FIELD`/`MEALKIT_VIEW_FIELD`/`MEALKIT_ARRAY`).
  `__COUNTER__`로 필드 번호를 매기고 실행 중 설명(`reflect::TypeInfo`)을 만들어, 타입을 모르는 엔진·에디터가 텍스트 저장, 해시, 스냅샷, 비교, 위젯을 처리한다.
  씬 물체는 `type` 이름(기본 `solid`/`decoration`/`spawn` + 게임 종류)과 필드 텍스트(`field <경로> <값>`)를 가진다(씬 파일 version 2, version 1도 읽는다).
  게임 코드가 없거나 필드가 바뀌어도 값은 보존된다. 게임 DLL은 `GameModule::objectTypes`로 종류를 넘기고(`kApiVersion` 3),
  에디터는 [추가] 메뉴·`+ 종류...`·인스펙터 "종류" 콤보와 필드 위젯(`editor/FieldEditor`)을 보여 준다. 게임은 `scene::readObject<T>(entity)`로 읽는다.
  예제: sandbox `JumpPad`(점프 힘, 재사용 대기) — 아레나에 하나 놓았다.
- **콘텐츠 해시**: 장식 종류(`kObjectCosmetic`)와 `MEALKIT_VIEW_FIELD`는 뺀다. 게임은 `scene.contentHash(&reflect::moduleObjectTypes())`.
- **왜**: 지금 에디터에 놓을 수 있는 물체 종류(`Solid`/`Decoration`/`SpawnPoint`)가 엔진 `Scene.h`에 박혀 있다. 코인·트리거·점프대를 만들려면 엔진을 고쳐야 한다.
- **방식**: 게임 코드가 타입과 필드를 한 번 선언하면 에디터의 `추가` 메뉴와 인스펙터에 자동으로 나타나고 `.scene`에 저장된다. `World`는 매치를 시작할 때 읽는다.
  ```cpp
  MEALKIT_OBJECT(JumpPad) {
      MEALKIT_FIELD(f32, power, 12.0f, "점프 힘");
      MEALKIT_FIELD(u32, cooldownTicks, 30, "재사용 대기(틱)");
  };
  ```
- **기존 종류**: 상자·장식·스폰도 이 시스템 위의 기본 타입으로 옮긴다. 기존 `.scene`은 그대로 읽히게 한다.
- **결정론**: 필드 값은 콘텐츠 해시에 포함한다(장식용 필드는 표시해서 제외). 순회는 오브젝트 id 순서.

### [x] 튜닝 값을 데이터로 (완료 2026-10-15)
- **구현됨**: 게임이 `MEALKIT_STRUCT(Tuning)`(sandbox `sim/Tuning.h`)을 선언하고 `GameSession::TuningType`으로 알린다(`GameModule::tuningType`, `kApiVersion` 4).
  값은 `assets/game.tuning`(텍스트 `경로 값`). `game::loadTuning`이 읽고 `World::reset`이 `world.tuning`으로 복사한다. 콘텐츠 해시는 `game::contentHash`(씬 + 모델 + 튜닝).
  에디터 [튜닝] 패널(환경 옆 탭)에서 고치고 저장(Ctrl+S도 같이)한다. 플레이를 누르면 저장 안 된 값을 `build\Editor\play\play.tuning`으로 넘기고,
  플레이 중에 고치면 `GameInstance::setTuning`으로 바로 적용한다(혼자 플레이). 게임 실행 파일은 `--tuning <파일>`로 다른 값을 쓸 수 있다.
  sandbox의 이동·점프·중력·밀치기·상자 밀도 상수를 튜닝으로 옮겼다(같은 값이라 상태 해시도 이전과 같다).
- **왜**: 이동 속도·점프력·쿨다운이 `World.cpp`의 `constexpr`이라 값 하나 맞추는 데도 빌드가 필요하다.
- **방식**: 위와 같은 필드 선언으로 게임 전역 설정(`assets/game.tuning` 같은 텍스트 파일)을 만들고 에디터 패널에서 고친다.
  에디터 혼자 플레이에서는 값을 바꾸면 바로 적용, 멀티플레이에서는 매치 시작 때 고정하고 콘텐츠 해시에 넣는다.

### [x] 상태 필드를 한 번만 선언 (완료 2026-10-15)
- **구현됨**: sandbox `WorldState`·`Player`·`Prop`·`Pad`를 `MEALKIT_STRUCT`/`MEALKIT_FIELD`로 선언했다. `World::hash()`는 `reflect::hashStruct`(선언한 필드 전부) + 물리 해시 한 줄이다.
  스냅샷: `game::saveSnapshot`/`loadSnapshot`(`mealkit/game/WorldSnapshot.h`, 상태 필드 + `PhysicsWorld::save/restore`).
  물리 스냅샷은 바디 목록·모양·Jolt 상태(`SaveState`)를 담고, 복원하면 그 사이에 만들거나 지운 바디도 되돌린다. 바디 id는 엔진이 정하는 순서로 매겨(`CreateBodyWithID`) 복원 뒤에 만든 바디도 같은 id가 된다.
  단위 테스트 `physics_snapshot`: 복원 후 40틱 동안 해시가 처음과 같다(중간에 바디 삭제·생성 포함).
  에디터 [상태] 패널(인스펙터 옆 탭, 플레이하면 앞으로)이 선언을 그대로 읽기 전용 표로 보여 준다(`GameInstance::stateView`, `kApiVersion` 5).
- **바뀐 것**: 바디 id 할당 방식이 바뀌어 상태 해시 값이 이전과 다르다(피어끼리는 같다, `mp_test` PASS).
- **왜**: 새 상태 하나에 구조체, `step`, `hash`, 그리기를 고쳐야 하고, `hash`를 빠뜨려도 조용히 디싱크 감지에서 빠진다. 중간 참가(스냅샷)를 넣으면 한 곳이 더 는다.
- **방식**: 시뮬레이션 상태도 필드 선언(위와 같은 장치)으로 만들고 **해시, 스냅샷 저장·복원, 에디터 실시간 보기**를 자동 생성한다. 3단계 "중간 참가"의 기반.

### [x] 결정론 수학 유틸 (삼각함수 근사) (완료 2026-10-15)
- **구현됨**: `mealkit/core/DetMath.h`(`detSin`/`detCos`/`detAtan`/`detAtan2`/`detQuatFromAxisAngle`/`detYawQuat`, Cephes 계수). CRT와의 최대 오차 sin·cos 6e-8, atan2 2.4e-7.
  엔진 단위 테스트 `mealkit_tests`(엔진 저장소 빌드)가 오차와 결과 비트 해시(`detmath-bits`)를 출력하고, Release·Editor 빌드에서 같은 해시를 확인했다. SimCheck SIM001 안내가 이 함수들을 가리킨다.
- **왜**: 시뮬레이션에서는 CRT `sin`/`cos`/`atan2`를 쓸 수 없는데, 엔진에 대신 쓸 함수가 없다(`quatFromAxisAngle`도 시뮬레이션 금지). 캐릭터 회전, AI 방향 전환, 래그돌 목표 포즈 모두 각도 계산이 필요하다.
- **방식**: `mealkit/core/DetMath.h`에 사칙연산과 `sqrt`만 쓰는 다항식 근사 `detSin`/`detCos`/`detAtan2`/`detQuatFromAxisAngle`. 입력 범위를 정수 연산으로 줄인 뒤(각도 → [-π/4, π/4]) 근사한다.
- **검사**: 모든 입력 구간에서 CRT 결과와의 오차 한계를 테스트하고, 결과 비트가 Release/Editor 구성에서 같은지 `mp_test`·해시로 확인한다. `sim/` 금지 헤더 검사는 CRT 함수 대신 이 함수를 쓰라고 안내한다.
- **비용**: 작음. 아래 "플레이어·캐릭터 분리"와 4단계 "이동 모드"의 전제.

### [ ] 플레이어와 캐릭터 분리 (빙의)
- **왜**: 지금은 `players[i]`가 접속한 사람이면서 동시에 캡슐 몸이다. 리스폰 대기, 관전, 차량 탑승, AI 캐릭터, 죽어도 남는 점수를 넣을 자리가 없다.
- **방식**: 시뮬레이션 상태를 세 가지로 나눈다.
  - `PlayerSlot`: 매치 동안 유지. 접속 상태, 이름, 팀, 점수, 이번 틱 입력.
  - `Pawn`: 월드 안의 몸(종류, 이동 모드, 체력 등). 생기고 사라지며 id 순서로 갱신.
  - `Controller`: 슬롯 또는 AI를 Pawn에 잇는다. 플레이어 / AI / 없음(관전). `possess(controller, pawnId)`, `unpossess(controller)`.
- **언리얼과 다른 점**: Actor 상속 트리는 만들지 않는다. 전부 시뮬레이션 안의 평평한 배열이고, 빙의 변경도 시뮬레이션 안에서만 일어난다(클라이언트는 입력으로 "탑승 요청"만 보낸다).
- **AI**: AI 컨트롤러는 시뮬레이션 안에서 결정론으로 돈다(모든 피어가 같은 계산, 대역폭 0). 지금의 `--bot`(입력을 만들어 보내는 방식)은 테스트 도구로 따로 둔다.
- **템플릿**: `sim/`·`view/` 구조와 같이 템플릿에 넣는다. 나중에 넣으면 만든 프로젝트를 모두 옮겨야 한다.
- **결정론**: 슬롯·Pawn·Controller 상태 모두 `hash()`에. Pawn 생성·삭제는 틱 안에서 정해진 순서로, id는 재사용하지 않거나 세대 번호를 붙인다.
- **이어지는 것**: 3단계 중간 참가(빈 슬롯 이어받기), 4단계 이동 모드·게임 흐름·데미지.

### [ ] 씬 트리 계층 (부모·자식)
- **왜**: 여러 물체를 묶어 옮기기, 움직이는 발판 위의 장식 같은 경우 부모·자식이 필요하다.
- **방식**: `Entity`에 `parent` id를 두고 에디터에서는 트리로 보여 준다(끌어서 부모 변경). **게임이 불러올 때 월드 좌표로 펼쳐** 실행 중에는 지금처럼 평평한 배열로 둔다(속도·결정론 유지). 4단계 "프리팹"과 이어진다.

### [ ] 에디터에서 여러 명으로 플레이
- **왜**: 멀티플레이 엔진인데 여러 명 테스트는 명령줄로 창을 직접 띄워야 한다.
- **방식**: 플레이 버튼 옆에서 "플레이어 2~4명"을 고르면 현재 씬(저장 안 된 편집 포함, 임시 파일로)으로 `--host --local` 창 1개 + 참가 창을 자동으로 띄운다.
  추가 창은 봇 입력 또는 직접 조작. 정지하면 모두 닫는다. 유니티 Multiplayer Play Mode에 해당.

### [ ] 그림자 시뮬레이션으로 디싱크 즉시 감지
- **왜**: 결정론 실수는 지금 `mp_test`를 돌려야 드러나고, 어디서 났는지 찾기 어렵다.
- **방식**: 에디터 플레이 중 같은 입력으로 `World`를 하나 더 돌리고 매 틱 해시를 비교한다. 다르면 즉시 멈추고 틱·상태 차이를 보여 준다.
- **잡는 것 / 못 잡는 것**: 초기화 안 된 변수, 포인터 주소 순서, 실제 시간 읽기, 전역 상태는 잡는다. CPU마다 다른 계산(FMA 등)은 못 잡는다(`mp_test`, 다른 PC 테스트로).
- **비용**: 시뮬레이션 CPU 2배 (에디터에서만, 끌 수 있게).

### [ ] 일시정지, 한 틱씩 진행, 되감기
- **왜**: 버그가 난 순간을 다시 보기 어렵다. 결정론이라 입력만 기록하면 어느 틱으로든 돌아갈 수 있다.
- **방식**: 에디터 플레이 중 입력을 기록하고 일정 간격(예: 5초)마다 스냅샷을 남긴다. 타임라인 슬라이더로 가까운 스냅샷에서 빨리 감아 원하는 틱으로 간다. 일시정지 중에는 상태 인스펙터로 값을 본다.
- **의존**: "상태 필드를 한 번만 선언"의 스냅샷 기능.

### [ ] 주기적 자동 저장
- **왜**: 지금은 에디터를 정상 종료할 때만 `.autosave`를 남긴다. 크래시가 나면 그 사이 작업이 사라진다.
- **방식**: 변경이 있으면 1~2분마다 `.autosave`에 쓰고, 다음 실행 때 복구할지 묻는다. 원본 파일은 덮어쓰지 않는다.

### [ ] 한 번에 도는 검증 스크립트 (`tools/check.ps1`)
- **왜**: 범용 에디터 작업 때 Editor 빌드, Release 빌드, 결정론 테스트, 에디터 플레이 캡처, 핫 리로드, 빌드 실패 처리, 출시 빌드를 매번 손으로 돌렸다. 엔진을 고칠 때마다 이걸 다 기억해서 돌리기 어렵다.
- **방식**: 위 과정을 차례로 실행하고 항목별 PASS/FAIL과 걸린 시간을 출력한다. 스크린샷은 `build\check\`에 남긴다. `-Quick`(빌드 + 결정론 테스트만) 옵션.
- **이후**: 헤드리스 시뮬레이션(4단계)이 생기면 GPU 없이 도는 부분을 늘린다.

### [ ] 프로젝트 업그레이드 도구 + 엔진 버전
- **왜**: 템플릿(`build.bat`, `.vscode`, `CMakeLists.txt` 형식)이 바뀔 때마다 기존 프로젝트를 손으로 옮겨야 한다(범용 에디터 작업 때 Sandbox를 손으로 옮겼다).
- **방식**: `tools/upgrade_project.ps1 <프로젝트>`가 템플릿이 관리하는 파일만 새로 쓰고 `source/`, `assets/`는 건드리지 않는다. 바꾸기 전 파일은 `.upgrade_backup/`에 남긴다.
  사용자가 고친 템플릿 파일(예: `CMakeLists.txt`의 SOURCES)은 덮어쓰지 않고 차이를 보여 준다.
- **엔진 버전**: 엔진에 `MEALKIT_VERSION`, `mealkit.project`에 `engineVersion=`. 에디터가 프로젝트를 열 때 버전이 다르면 업그레이드를 권한다.

### [ ] 코드 서식 통일 (`.clang-format`, `.editorconfig`)
- **왜**: 프로젝트가 여러 개가 되거나 AI로 코드를 짜도 스타일이 일관되게. 지금 스타일(4칸, 120열, 중괄호 같은 줄)을 규칙 파일로 고정한다.
- **방식**: 엔진과 프로젝트 템플릿에 넣고, VS Code에서 저장할 때 자동 서식. `third_party/`는 제외. 비용 거의 없음.

## 1단계 (v0.5): 게임이 되게 하는 최소 기능

게임을 실제로 내놓으려면 빠져서는 안 되는 기능. 대부분 렌더링·시뮬레이션과 독립적이라 결정론 위험이 낮다.

### [ ] 오디오
- **왜**: 지금 엔진에는 소리가 전혀 없다. 효과음·배경음 없이는 게임이 되지 않는다.
- **방식**: XAudio2(Windows 기본 포함, 새 의존성 없음). 효과음은 WAV, 배경음은 Ogg Vorbis 스트리밍.
- **API 초안**: `audio::Engine::play(SoundId, Vec3 position, f32 volume)`, 리스너 = 카메라. 3D 감쇠·좌우 패닝(X3DAudio).
- **라이브러리 후보**: `stb_vorbis` (퍼블릭 도메인, 파일 하나)로 Ogg 디코딩.
- **결정론**: 소리는 렌더링처럼 **결과만 읽는다.** 시뮬레이션이 "이벤트"(충돌, 점프)를 남기면 프레임 쪽에서 재생한다. 시뮬레이션이 오디오 상태를 읽으면 안 된다.
- **비용**: CPU 코어 하나의 1% 미만. 개발 중간.

### [ ] 게임 화면 UI (Penpot 디자인 → `.ui` 런타임)
- **왜**: 지금은 점수·로비 상태를 창 제목으로만 보여 준다. 게임 UI는 프로그래머가 아닌 사람도 UMG·UI Toolkit처럼 시각적으로 디자인할 수 있어야 한다.
- **구조**: **Penpot이 원본이고 엔진은 가져오기만 한다.**
  - 디자이너가 Penpot(오픈소스 웹 디자인 도구, 직접 서버를 띄울 수도 있다)에서 화면을 만든다.
  - 엔진 저장소의 Penpot 플러그인(`tools/penpot-plugin/`, TypeScript)이 지원 범위를 검사하고 `.ui`(텍스트, 키는 영어)와 이미지로 내보낸다.
  - 엔진은 `.ui`를 유지 모드 런타임(`mealkit/ui/`)으로 그린다. 에디터 안에 UI 디자이너는 만들지 않는다.
- **원본 규칙**: `assets/ui/*.ui`는 생성물이라 손으로 고치지 않는다(첫 줄에 표시, Penpot 파일·보드 id 기록).
  바인딩·액션까지 전부 Penpot 안(플러그인 데이터)에 두어 엔진에서 고칠 것이 없게 한다(왕복 없음). Penpot 원본은 `.penpot` 파일로 내보내 프로젝트 `design/`에 백업한다.
- **가져오는 길**: 에디터가 localhost 서버를 연다.
  - 플러그인 파일을 제공한다(디자이너는 그 주소로 플러그인을 설치).
  - 플러그인이 보낸 `.ui`·이미지를 `assets/ui/`에 쓰고 핫 리로드한다. Penpot에서 고치면 수 초 안에 엔진 화면에 보인다.
  - 게임 DLL의 뷰 모델 필드 목록과 액션 목록을 플러그인에 알려 준다(바인딩을 드롭다운으로 고른다).
  - 에디터가 없을 때는 플러그인이 zip으로 내려받게 한다. Penpot 클라우드(penpot.app)로 시작하고 필요하면 직접 띄운다.
  - 플러그인에서 localhost로 보내는 방법(권한, CORS)은 도입 때 확인한다.
- **지원 범위** (플러그인이 내보내기 전에 검사하고, 벗어나면 경고):

  | Penpot | 엔진 |

  | 안쪽 그림자, 블렌드 모드, 마스크, 불리언 도형, 패스, 아이콘 | PNG로 구워 아틀라스에(2배 해상도) |
  | 레이어 블러, 배경 블러 | 미지원(경고). 내장 그래픽에서 비싸다 |
  | 이미지 채우기 | PNG로 내보냄. 9-slice는 플러그인에서 여백 지정 |

- **글자 (여러 스타일을 처음부터 지원)**:
  - Penpot 글자 구조(문단 → 스타일 구간)를 그대로 가져온다. 구간마다 글꼴·굵기·기울임·크기·색·자간·밑줄·취소선·대소문자 변환, 문단마다 정렬·줄 높이.
  - 줄바꿈은 구간 경계를 넘어 한 번에 계산한다. 한글 줄바꿈 단위(음절 / 어절), 줄 높이·기준선 계산은 Penpot 결과에 맞추고 픽셀 비교로 확인한다.
  - 자동 크기(너비·높이 / 높이 / 고정), 넘치면 말줄임.
  - 글꼴: `stb_truetype`(퍼블릭 도메인, 파일 하나)로 **쓰는 글자만 실행 중에 SDF로 구워** 아틀라스 캐시에 넣는다. 굵기·기울임마다 글꼴 파일 하나.
    미리 굽는 완성형 2,350자 방식은 쓰지 않는다(드문 한글, Steam 닉네임의 일본어 등을 못 보여 준다). 기본 글꼴 후보는 Pretendard, Noto Sans KR(OFL).
    Penpot에서 쓴 글꼴·굵기가 `assets/fonts/`에 다 있는지 플러그인이 검사한다. 글자 모양 조합(HarfBuzz)은 하지 않는다(한·영·일은 필요 없음).
- **게임 코드와 연결**: 단방향 뷰 모델 + 액션. 방법은 이것 하나다.
  ```cpp
  // 게임 코드가 선언하면 플러그인의 바인딩 목록에 나타난다
  MEALKIT_VIEWMODEL(HudVm) {
      MEALKIT_FIELD(u32, score, 0, "점수");
      MEALKIT_FIELD(f32, health01, 1.0f, "체력 비율");
      MEALKIT_LIST(PlayerRowVm, players, 4, "플레이어 목록");
  };
  void fillHud(const World& world, u8 me, HudVm& vm); // 매 프레임: 상태 → 뷰 모델
  void onUiAction(ui::Action action, AppState& app);  // 버튼 → "pause.resume" 같은 액션
  ```
  - 글자 바인딩은 글자 안에 `{score}`를 그냥 쓴다(그 구간의 스타일을 따른다). 서식은 정해진 몇 가지만(천 단위 구분, 소수 자릿수, 시간).
  - 그 밖의 바인딩(보이기, 너비 비율, 이미지, 색 토큰, 비활성)과 위젯 종류(버튼, 토글, 슬라이더, 선택 상자, 글자 입력, 스크롤 영역, 목록)는 플러그인 패널에서 정한다. 정하지 않은 것은 그림이다.
  - 버튼은 플러그인 패널에 액션 이름을 적는다. 입력 위젯만 자기 필드에 값을 쓰고 `changed` 액션을 낸다. 양방향 바인딩, 식 언어, 변환기는 없다.
  - 목록은 자식 하나를 반복 템플릿으로 표시하고 배열 필드에 묶는다. 나머지 예시 자식은 미리보기에서만 쓴다.
- **컴포넌트·상태·테마**:
  - Penpot 컴포넌트 = 재사용 `.ui`(인스턴스 덮어쓰기 반영).
  - 상태(보통 / 마우스 올림 / 눌림 / 포커스 / 비활성)는 컴포넌트 variants로 만든다. 쓰는 Penpot 버전에 variants가 없으면 `Button/Hover` 이름 규칙.
  - 전환 시간·이징은 테마 기본값, 컴포넌트별로 플러그인에서 덮어쓴다. 프로토타입 흐름과 애니메이션은 가져오지 않는다.
  - Penpot 디자인 토큰(색·숫자) = 테마 토큰(`assets/ui/theme`). 토큰 세트(예: 색약 모드)는 테마 변형으로.
- **게임패드·키보드 조작**: 포커스는 위젯 id로 기억하고, 방향 입력이 오면 그 방향에서 가장 가까운 위젯으로 옮긴다. 필요한 곳만 플러그인에서 "다음 포커스"를 지정한다.
  확인·뒤로·이동은 입력 액션 매핑의 액션이다. 버튼 안내 아이콘(키보드 / Xbox)은 마지막에 쓴 기기를 따라간다. 마우스를 움직이면 포커스 표시를 숨긴다.
- **런타임**:
  - `.ui`를 불러오면 포인터 없는 평평한 노드 배열(부모 번호, 깊이 우선 순서)이 된다. 바인딩 값이나 화면 크기가 바뀐 노드만 다시 배치한다(가만히 있는 화면은 CPU 거의 0).
  - 좌표는 기준 보드(1920×1080)의 논리 단위, 배율 = `min(가로/1920, 세로/1080) × 설정의 UI 배율`.
  - 그리기는 3D 장면 다음의 2D 패스 하나: 이미지 아틀라스 + 글자 아틀라스 + SDF 도형을 SM 6.6 bindless로 묶어 드로우 콜 1~2회. 동적 해상도와 무관하게 원래 해상도로 그린다.
  - UI 이미지는 WIC(Windows 기본 이미지 디코더, 새 의존성 없음)로 PNG를 읽는다. 3D 머티리얼 텍스처는 2단계 그대로.
- **월드 위 UI**: 이름표·데미지 숫자·목표 표시는 `.ui` 템플릿을 3D 위치에 붙여 여러 개 띄운다. 화면 밖·카메라 뒤면 숨기거나 가장자리에 붙인다.
- **에디터 UI 미리보기 패널**: 해상도 전환(720p / 1080p / 21:9 / 4:3 / UI 배율), 가짜 뷰 모델 값, 언어 전환(글자 넘침 확인), 포커스 이동 표시, 바인딩 오류 목록(없는 필드·액션), 화면별 노드 수.
- **검증**: 플러그인이 같은 보드를 Penpot PNG로도 내보내고, 엔진 `--capture` 결과와 픽셀 차이를 비교한다(`tools/check.ps1`에 포함).
  화면당 노드 수 예산은 500개, 효과 없는 래퍼 보드는 플러그인이 납작하게 만든다.
- **결정론**: 영향 없음 (`view/`에서만). UI는 시뮬레이션 상태를 읽기만 하고, 액션은 입력이나 `AppState` 변경만 만든다.
- **순서**: `.ui` 런타임(이때는 `.ui`를 텍스트로 고쳐 핫 리로드) → 플러그인 내보내기 + 에디터 가져오기 서버 → 미리보기 패널 → 픽셀 비교 검사.
- **의존**: 0단계 필드 선언(뷰 모델), 로컬라이제이션(아래), 입력 액션 매핑.
- **비용**: 큰 항목(런타임 + 플러그인). 글꼴 파일 약 2~5 MB(에셋), 글꼴 라이선스를 `THIRD_PARTY_NOTICES.txt`에. 플러그인 빌드에 Node.js가 필요하다(개발 도구, 게임에는 들어가지 않는다).
- **이어지는 것**: 로비·일시정지 메뉴는 아래 "기본 화면 흐름 템플릿", 설정 화면은 "설정 시스템 + 표준 설정 화면"에서 Penpot 원본과 `.ui`로 만든다.

### [ ] 디버그 UI (Dear ImGui)
- **왜**: 성능·치트·시뮬레이션 상태·디싱크 정보 같은 개발용 화면은 프로그래머가 코드로 빨리 만드는 게 맞다. 게임 UI(Penpot)와 섞지 않는다.
- **방식**: 게임 코드는 `GameContext`로 받은 ImGui로 패널을 그린다. Editor 빌드에서는 에디터의 ImGui 컨텍스트를 게임 DLL에 넘긴다(DLL마다 ImGui 전역이 따로라서 `ImGui::SetCurrentContext`).
  Dev 게임 빌드에서는 게임 창 위의 오버레이(키 하나로 켜고 끔). 출시 빌드에서는 `MEALKIT_DEBUG_UI`로 코드가 빠지고 ImGui를 링크하지 않는다.
- **결정론**: 디버그 패널이 시뮬레이션을 바꾸는 치트는 상태를 직접 고치지 않고 락스텝 입력(디버그 명령)으로 보낸다. 직접 고치면 다른 피어와 그림자 시뮬레이션이 디싱크된다.
- **이어지는 것**: 4단계 "디버그 그리기 API", "성능 패널과 예산 경고"가 이 위에 놓인다.

### [ ] 로컬라이제이션 문자열 테이블
- **왜**: UI를 만들면서 문자열을 코드에 바로 쓰면, 나중에 영어를 넣을 때 모든 문자열을 찾아 바꿔야 한다.
- **방식**: `assets/strings/ko.txt`, `en.txt`(키 = 문자열). Penpot 글자에는 플러그인이 키를 붙이고(기본값은 레이어 이름), 게임 코드는 `L("menu.start")`처럼 키만 쓴다. 언어는 설정에서 고르고, 없는 키는 키 이름을 그대로 보여 주고 로그를 남긴다.
- **여러 스타일 글자**: 한 글자 상자에 스타일 구간이 여럿이면 문자열에 번호 태그를 쓴다: `점수 <1>{score}</1>점`. 번호는 디자인의 구간 순서이고, 번역할 때는 태그 위치만 옮긴다.
  플러그인은 처음 내보낼 때 한국어 원문을 태그와 함께 `ko.txt`에 넣고, 이미 있는 키는 덮어쓰지 않고 차이만 경고한다.
- **글꼴**: 테이블에 있는 글자가 모두 글꼴 파일에 들어 있는지 빌드 때 검사한다(글자는 실행 중에 굽는다).
- **결정론**: 영향 없음 (화면 쪽만, 콘텐츠 해시에 넣지 않는다).

### [ ] 입력 액션 매핑
- **왜**: 게임 코드가 `'W'`, `Space` 같은 키를 직접 확인한다. 키 바꾸기 설정, 게임패드, 봇 입력을 따로따로 처리해야 한다.
- **방식**: 게임이 액션("이동"은 2축, "점프"·"밀치기"는 버튼)을 선언하고, 키보드·마우스·게임패드 바인딩을 데이터(`assets/input.bindings`)로 둔다. 게임 코드는 액션 값만 읽는다.
  플레이어가 바꾼 키는 사용자 설정 폴더에 저장한다(콘텐츠 해시와 무관).
- **결정론**: 영향 없음. 액션 값은 지금처럼 `GameInput` 8바이트로 양자화해 보낸다.
- **같이 할 것**: 게임패드(아래)를 이 위에 만든다.

### [ ] 게임패드
- **방식**: XInput (Windows 기본 포함). 입력 액션 매핑의 바인딩 소스로 추가. 스틱 데드존, 트리거.
- **결정론**: 이미 입력 단계에서 양자화하므로 영향 없음.
- **비용**: 작음. 하루 이틀.

### [ ] 설정 시스템 + 표준 설정 화면
- **왜**: 거의 모든 게임이 화면·소리·키 설정을 같은 모양으로 다시 만든다. 엔진이 기본 화면을 주고 게임은 항목만 더하게 한다.
- **방식**: 0단계 필드 선언(`MEALKIT_FIELD`)으로 설정 스키마를 만들고, 탭이 있는 설정 화면을 Penpot 원본 + `.ui`로 기본 제공한다. 항목 줄은 목록 바인딩으로 스키마에서 채우므로, 게임은 디자인을 고치지 않고 탭·항목을 추가할 수 있다.
- **사용자 데이터 폴더**: `%LOCALAPPDATA%\<게임>\`에 `settings.ini`, 키 바인딩, 세이브·통계, 리플레이, 크래시 리포트를 한 규칙으로 둔다. 세이브는 버전 번호를 붙여 형식이 바뀌어도 읽게 한다.
- **기본 항목**:
  - 화면: 창 모드(창 / 테두리 없는 창 / 전체화면), 해상도, 수직동기, 프레임 제한, 렌더 스케일(동적 해상도와 연결), 그래픽 프리셋(내장 그래픽이 기본), FOV, 밝기.
  - 오디오: 마스터 / 배경음 / 효과음 / UI 볼륨(XAudio2 서브믹스 보이스), 창이 포커스를 잃으면 음소거.
  - 키: 입력 액션 매핑 위의 키 바꾸기 화면, 중복 키 경고, 기본값 복원, 게임패드 감도·축 반전.
  - 게임플레이·접근성: 마우스 감도, Y축 반전, 언어, UI 배율, 자막.
- **화면 변경 확인**: 해상도·창 모드를 바꾸면 "15초 안에 확인하지 않으면 되돌림" 창을 띄운다.
- **결정론**: 설정은 콘텐츠 해시에 넣지 않고 **시뮬레이션이 읽으면 안 된다**. `sim/` 금지 헤더 검사에 설정 헤더도 넣는다. 감도·반전처럼 조작에 닿는 값은 입력을 양자화하기 전에 클라이언트에서만 적용한다.
- **의존**: 오디오, 게임 UI, 입력 액션 매핑, 게임패드.

### [ ] 기본 화면 흐름 템플릿
- **왜**: 타이틀부터 결과 화면까지의 흐름도 게임마다 비슷하다. 지금은 명령줄 옵션으로 호스트·참가를 고른다.
- **방식**: 타이틀 → 메인 메뉴 → 방 만들기 / 참가(IP 또는 Steam 초대) → 로비(준비, 팀) → 로딩 → 게임 → 일시정지(설정 열기, 나가기) → 결과 → 로비로. 프로젝트 템플릿에 화면별 Penpot 원본(`design/`)과 `.ui`, 뷰 모델·액션 코드로 넣어 게임이 고쳐 쓴다.
- **결정론**: 화면 흐름은 `view/`·`app/` 쪽. 매치 안의 상태(카운트다운, 결과)는 4단계 "게임 흐름 프레임워크"가 시뮬레이션에서 정하고, 화면은 그것을 읽기만 한다.

### [ ] 네트워크 상태 흉내 내기
- **왜**: 같은 PC 테스트는 지연이 0에 가깝다. 입력 지연 자동 조절, 끊김 처리, 재접속을 실제 친구 없이 시험할 수 없다.
- **방식**: `--net-lag <ms> --net-jitter <ms> --net-loss <%>` 옵션. `net::Transport` 위에 지연 큐와 무작위 손실을 두는 래퍼(UDP, Steam 모두). `mp_test.ps1`에도 같은 옵션.
- **결정론**: 영향 없음(전달 시점만 바뀐다). 손실은 실제 패킷 손실과 같은 재전송 경로를 탄다.
- **비용**: 작음. 입력 지연 자동 조절보다 먼저 한다.

### [ ] 버전 표시와 접속 거부 이유
- **왜**: 지금은 exe·씬·모델이 다르면 콘텐츠 해시가 달라 접속이 거부되지만, 친구는 이유를 알 수 없다.
- **방식**: exe에 게임 버전 + 빌드 번호(git 커밋)를 넣어 창 제목·로비에 표시한다. 접속 때 버전과 해시 구성(exe/씬/모델)을 따로 보내, 거부할 때 "게임 버전이 다릅니다 (내 1.2 / 방장 1.3)", "씬 파일이 다릅니다"처럼 알려 준다.
- **같이 할 것**: 출시 폴더 이름에 버전(`export\<이름>-1.2\`) 옵션.

### [ ] Steam 실검증
- **왜**: SDK(v1.65)로 컴파일·링크만 확인했다. 실제 로비·초대·릴레이는 아직 검증하지 않았다.
- **할 일**: 두 계정(또는 두 PC)으로 `--steam` → 초대 → `+connect_lobby` 참가 → 900틱 이상 디싱크 없음 확인. 끊김·재시도·NAT 상황 로그.
- **같이 할 것**: Steam 오버레이가 DX12 스왑체인 위에 뜨는지 확인.

### [ ] 입력 지연 자동 조절
- **왜**: 지금은 `--delay 3`(100 ms) 고정이다. LAN에서는 너무 길고, 먼 상대에게는 짧아서 멈칫거린다.
- **방식**: 호스트가 피어별 RTT를 보고 매치 시작 때(그리고 진행 중에는 천천히) 입력 지연을 정해 모두에게 같은 틱부터 적용한다.
- **결정론**: 지연 변경 자체를 틱 번호와 함께 확정 입력으로 보내야 한다.

### [ ] 내 캐릭터 겉모습만 예측
- **왜**: 입력 지연(약 100 ms) 때문에 내 조작이 늦게 느껴진다. 롤백 넷코드는 비용이 너무 크다(보류 표).
- **방식**: 시뮬레이션은 그대로 두고, 화면에서만 내 캐릭터를 아직 확정되지 않은 내 입력으로 미리 움직여 그린다. 확정 상태가 오면 부드럽게 맞춘다.
- **결정론**: 영향 없음 (`view/`에서만 한다). 다른 플레이어·물체와의 충돌은 확정 후에 보인다.

### [ ] 틱레이트를 프로젝트 설정으로
- **왜**: 30 Hz 고정. 물체가 적은 액션 게임은 60 Hz가 반응·충돌 정확도에 낫다.
- **방식**: 프로젝트 설정 `tickRate`(30 기본, 60 선택). 콘텐츠 해시에 포함.
- **비용**: 60 Hz는 시뮬레이션 CPU와 입력 패킷이 2배. 바디 수천 개짜리 게임에는 쓰지 않는다.

## 2단계 (v0.6): 보기 좋게 (그래픽)

모두 **끌 수 있는 옵션**으로 넣고, 내장 그래픽 프리셋을 기본값으로 둔다.

### [ ] 벤치마크 모드 (그래픽 작업 전에 먼저)
- **왜**: 성능 예산의 "현재" 값은 최소 사양보다 빠른 PC에서 잰 것이다. 그래픽 기능을 넣을 때마다 같은 조건으로 비교할 기준이 없다.
- **방식**: `--benchmark [초]`: 고정 시드, 고정 카메라 경로, 봇 입력으로 돌리고 평균·1% 최악 프레임, GPU 시간, 틱당 시뮬레이션 시간, 드로우 콜을 텍스트 보고서(`benchmark.txt`)로 남긴다. GPU 이름·드라이버도 기록.
- **쓰임**: 최소 사양(11세대) 실기 측정, 그래픽 기능 전후 비교, 친구 PC 성능 받기(출시본에도 들어 있다). 성능 예산 표를 이 결과로 갱신한다.

### [ ] 프러스텀 컬링
- **왜**: 지금은 화면 밖 물체도 모두 인스턴스 버퍼에 넣는다. 맵이 커지면 바로 비용이 된다.
- **방식**: `DrawList::add` 전에 바운딩 구로 CPU 컬링. 물체가 수만 개가 되면 메시별 묶음 단위로 먼저 걸러낸다.
- **비용**: 작음. 다른 그래픽 기능보다 먼저 한다.

### [ ] 텍스처와 머티리얼
- **방식**: glTF의 baseColor 텍스처를 불러올 때 **BC7(색)/BC5(법선)으로 압축**해 캐시 파일로 저장. 밉맵 포함.
  **Shader Model 6.6 bindless**(`ResourceDescriptorHeap[index]`)로 인스턴스의 텍스처 인덱스를 셰이더가 바로 읽는다(드로우 콜 수 유지). 최소 사양 11세대 결정으로 가능해졌다.
- **먼저 확인**: 11세대(Xe-LP) 실기에서 SM 6.6과 리소스 바인딩 티어 3 지원을 확인한다. 셰이더 프로파일을 `vs_6_6`/`ps_6_6`으로 올린다.
- **라이브러리 후보**: 이미지 디코딩 `stb_image`(퍼블릭 도메인), BC7 압축 `bc7enc_rdo`(MIT/퍼블릭 도메인). 압축은 에디터/불러오기 때만, 게임은 압축된 결과만 읽는다.
- **정점 형식**: UV를 추가하면 정점이 28 → 36바이트. 텍스처 없는 메시는 지금 형식을 유지할지 검토.

### [ ] 그림자
- **방식**: 태양 방향 그림자 맵 1~2단계(CSM), 1024² ~ 2048². 플레이어 주변만 높은 해상도.
- **예산**: 내장 그래픽에서 1.5 ms 이하. 넘으면 설정에서 끄거나 1단계로.

### [ ] 스켈레탈 애니메이션
- **왜**: 지금 캐릭터는 상자/캡슐이다. 사람·동물 캐릭터를 쓰려면 필요하다.
- **방식**: cgltf가 이미 skin/animation을 읽는다. CPU에서 포즈 샘플링 + GPU 스키닝(뼈 행렬 버퍼), 뼈 64개 제한.
- **결정론**: 화면용 애니메이션은 **보이기만** 한다. 히트박스·판정은 시뮬레이션의 캡슐로 한다. 화면용 애니메이션 결과가 시뮬레이션에 들어가면 안 된다.
- **시뮬레이션용 포즈 샘플링** (액티브 래그돌용, 결정 기록 참고): 래그돌 목표 포즈처럼 시뮬레이션이 써야 하는 포즈는 화면용과 **다른 경로**로 샘플링한다.
  시간은 틱 번호(실수 시간 아님), 보간은 사칙연산 `nlerp`와 결정론 수학 유틸만, 키프레임은 불러올 때 고정 순서로 굽는다. 결과는 `sim/`에서만 쓰고 화면용 애니메이션과 섞지 않는다.

### [ ] 파티클
- 먼지, 불꽃, 타격 효과. CPU 갱신 + 인스턴스 쿼드, 결정론 밖(오디오와 같은 이벤트 방식).

### [ ] 동적 해상도
- GPU 시간이 예산을 넘으면 3D 해상도를 낮추고 업스케일. UI는 원래 해상도로 그린다.

## 4단계 (v0.8): 게임플레이 프레임워크와 툴

### [ ] 게임 흐름 프레임워크 (GameMode / GameState)
- **왜**: 라운드, 타이머, 팀, 점수, 승리 조건은 거의 모든 멀티플레이 게임이 다시 만든다. 지금 sandbox는 매치 시작·끝 개념이 없다.
- **방식**: 시뮬레이션 안의 매치 상태 머신 `대기 → 카운트다운 → 진행 → 라운드 끝 → 결과 → (다음 판)`. 상태 전환은 틱 번호로 정하고(실수 타이머 없음), 규칙(라운드 수, 제한 시간, 승리 조건, 팀 수)은 튜닝 데이터로 둔다.
  게임은 전환 시점 콜백(`onRoundStart`, `onPawnDied` 등)만 구현한다. 점수판은 `PlayerSlot`에 둔다.
- **결정론**: 매치 상태 전부 `hash()`에. 화면(1단계 "기본 화면 흐름")은 이 상태를 읽기만 한다.
- **의존**: 0단계 플레이어·캐릭터 분리.

### [ ] 캐릭터 이동 모드
- **왜**: 지금 sandbox의 물리 캡슐 하나뿐이다. 게임마다 원하는 조작감이 달라 매번 이동 코드를 새로 짠다.
- **방식**: 상속이 아니라 Pawn 종류마다 **이동 모드 + 튜닝 데이터**를 고른다. 입력(`GameInput`) → 이동 의도(방향, 점프 등) → 모드별 처리 → 물리.

  | 모드 | 방식 | 어울리는 게임 | 주의 |
  |---|---|---|---|
  | 키네마틱 (기본) | Jolt `CharacterVirtual` | 정확한 조작, 계단·경사·움직이는 발판 | 결정론을 `mp_test`로 먼저 검증 |
  | 물리 캡슐 (지금 sandbox) | 리지드바디 + 속도 제어 | 밀치기 파티 게임 | 계단·경사가 어색함 |
  | 플로팅 | 아래로 레이캐스트 + 스프링·감쇠로 띄움 | 물리 상호작용 + 부드러운 이동 | 스프링 튜닝 값 필요 |
  | 액티브 래그돌 | Jolt `Ragdoll` + 모터가 목표 포즈를 따라감 | 몸 개그 물리 게임 | 아래 참고 |

- **순서**: 키네마틱 → 플로팅 → 액티브 래그돌. 물리 캡슐은 지금 코드를 모드로 옮긴다.
- **액티브 래그돌**: 2단계 스켈레탈 애니메이션의 "시뮬레이션용 포즈 샘플링"에 의존한다. 비용은 캐릭터당 바디 약 11~15개와 컨스트레인트. 4인 기준 틱 예산(4 ms) 안인지 벤치마크로 확인하고, 넘으면 관절 수를 줄인 간이 래그돌을 쓴다.
- **결정론**: 모든 모드는 Pawn id 순서로 처리하고, 각도 계산은 결정론 수학 유틸만 쓴다. 모드별 상태는 `hash()`에.

### [ ] 카메라 템플릿
- **왜**: 카메라는 조작감의 절반인데 게임마다 처음부터 만든다.
- **방식**: 3인칭 스프링암(벽에 부딪히면 당김), 1인칭, 탑다운, 관전 자유 카메라(빙의 없음일 때), 화면 흔들림(시뮬레이션 이벤트로). 카메라는 빙의한 Pawn을 따라간다.
- **결정론**: 영향 없음 (`view/`에서만). 지금처럼 이동 방향을 카메라 기준으로 계산해 월드 방향으로 양자화해 보낸다. 벽 충돌 레이캐스트는 화면용 질의로, 시뮬레이션 상태를 바꾸지 않는다.

### [ ] 데미지·체력 기본형
- **왜**: 대부분의 게임에 체력, 맞음, 죽음, 리스폰이 있다.
- **방식**: 히트 질의(구·캡슐·레이), 데미지 이벤트(가해자, 양, 종류), 체력, 무적 틱, 사망 → Pawn 제거 → 리스폰 대기(관전) → 새 Pawn에 빙의. 게임은 데미지 계산 규칙만 바꾼다.
- **결정론**: 히트 질의 결과는 id 순서로 정렬해 처리한다. 맞는 소리·효과는 이벤트로 남겨 화면 쪽에서 재생한다.
- **의존**: 플레이어·캐릭터 분리, 게임 흐름 프레임워크.

### [ ] 기본 오브젝트 종류 (트리거, 움직이는 발판, 아이템)
- **왜**: 대부분의 게임이 쓰는 종류를 엔진이 미리 제공해, 프로젝트마다 다시 만들지 않게 한다.
- **방식**: 0단계의 오브젝트 타입 시스템 위에 만든다: 트리거 볼륨, 경로를 따라 움직이는 키네마틱 발판, 아이템 스폰 지점. 범용 ECS는 만들지 않는다(가벼움).
- **결정론**: 오브젝트 id 순서로 갱신, 새 상태는 `hash()`에.

### [ ] AI 길찾기 (그리드 / 웨이포인트)
- **왜**: AI 컨트롤러가 장애물을 돌아가려면 경로가 필요하다.
- **방식**: 에디터에서 씬 충돌 데이터로 2D 그리드(높이 층 포함)를 굽거나 웨이포인트를 놓고, 시뮬레이션에서 A*로 찾는다. 새 외부 라이브러리 없음. 결과는 에디터 디버그 그리기로 확인.
- **결정론**: 구운 데이터는 콘텐츠 해시에 넣는다. A*의 동점 처리는 노드 번호로 고정하고, 한 틱에 찾는 경로 수를 제한해 순서대로 처리한다.
- **Recast 내비메시**는 보류 표 참고.

### [ ] 프리팹
- 여러 물체 묶음을 파일로 저장하고 씬에 여러 번 배치. 에디터의 복제를 확장.

### [ ] 에셋 핫 리로드 (모델·텍스처·씬)
- 에디터가 `assets/` 변경을 감지(`ReadDirectoryChangesW`)해 모델·텍스처·씬을 다시 읽는다. Blender에서 내보내면 바로 반영.

### [ ] 에디터 에셋 브라우저
- `assets/` 트리, 모델 미리보기 썸네일, 끌어서 씬에 놓기.

### [ ] 하이트맵 지형
- 하이트맵 + 청크 LOD 렌더링, Jolt `HeightFieldShape` 충돌. 에디터 브러시(올리기/내리기/평탄화).

### [ ] Job System
- 렌더링 준비(컬링, 인스턴스 채우기, 애니메이션 포즈)를 병렬화. 물리는 이미 Jolt 스레드 풀을 쓰므로 같은 워커를 나눠 쓸지 검토.

### [ ] 크래시 리포트
- 예외 핸들러에서 미니덤프 + 로그를 `crash/`에 저장. 친구 PC에서 난 문제를 재현할 때 필요.

### [ ] Steam 업적·리더보드·통계
- 1단계 Steam 실검증 다음. 게임이 업적 조건을 시뮬레이션 이벤트(라운드 승리, 처치 수)로 정하고, 화면 쪽이 이벤트를 읽어 Steam에 기록한다. Steam이 없으면 사용자 데이터 폴더의 통계에만 남긴다.
- **결정론**: 영향 없음 (결과만 읽는다).

### [ ] 프로젝트 namespace 정리
- 새 프로젝트를 만들 때 게임 코드의 `namespace sandbox`를 프로젝트 이름으로 바꾼다. (새 프로젝트 만들기 자체는 0단계 프로젝트 관리자로 옮겨 간다.)

### [ ] 에셋 쿠킹 + 팩 파일
- **왜**: 지금은 게임이 실행될 때마다 glTF를 파싱하고 meshoptimizer로 최적화·LOD를 만든다. 원본 에셋도 출시 폴더에 그대로 노출된다.
- **방식**: 출시 빌드 때 모델·씬·텍스처를 엔진 전용 바이너리로 바꿔 팩 파일 하나(`<이름>.pak`)에 담는다. 에디터는 계속 원본을 쓴다.
- **효과**: 로딩이 거의 즉시, 출시 exe에서 cgltf·meshoptimizer 제거.
- **주의**: 물리 껍질 점은 최적화 전 원본 정점에서 뽑아야 한다(결정론). 콘텐츠 해시는 쿠킹 결과 기준으로 계산하고, "에디터에서는 되는데 게임에서는 다르다" 버그를 막도록 에디터 플레이에서도 쿠킹본으로 돌려 보는 옵션을 둔다.

**에디터·디버깅 편의** (아래 항목들)

### [ ] 헤드리스 시뮬레이션
- 창과 GPU 없이 `World`만 N틱 돌리는 모드(`--headless`). 규칙 테스트가 몇 초로 끝나고, CI·AI로 자동 검증하기 쉽다. `mp_test`도 렌더링 없이 돌 수 있게 한다.

### [ ] 디버그 그리기 API
- 게임 코드에서 `debug::line`, `debug::box`, `debug::text`로 판정 범위·경로를 그린다. 에디터와 Dev 빌드에서만 보이고, 출시 빌드에서는 코드가 빠진다.
  `sim/`에서 부를 때는 그리기 요청만 기록한다(시뮬레이션이 렌더링 상태를 읽지 않게).

### [ ] 성능 패널과 예산 경고
- 프레임·틱·네트워크·드로우 콜을 이 문서의 성능 예산과 함께 보여 주고, 넘으면 빨갛게 표시한다. 지금은 상태 표시줄과 창 제목에만 나온다.

### [ ] 에러·오브젝트에서 코드로 이동
- 빌드 로그·런타임 로그의 `파일:줄`을 클릭하면 VS Code에서 그 줄을 연다(`code -g file:line`).
- 인스펙터의 오브젝트 타입 옆 "코드 열기"로 그 타입의 선언으로 간다.

### [ ] 로그 콘솔 창
- 지금 로그는 stdout으로만 나간다. 에디터 안에서 레벨별 필터·검색.

### [ ] 다중 선택
- 지금은 한 번에 하나만 선택된다. 드래그 박스 선택, Shift 클릭, 여러 개를 한 번에 이동·복제·삭제.

### [ ] 스냅·정렬 설정
- 그리드 크기, 회전 단위, 바닥에 붙이기, 정렬·균등 배치.

### [ ] 씬 여러 개 다루기
- 레벨 목록, 게임 시작 씬 지정, 에디터에서 씬 전환.

### [ ] 프로젝트 템플릿 여러 종류
- 빈 프로젝트, 아레나 대전(지금 예제), 레이싱·협동 같은 장르별 템플릿. 에디터의 "새 프로젝트"에서 고른다.

### [ ] 여기서 플레이
- 에디터 카메라 위치나 선택한 스폰 지점에서 바로 플레이를 시작한다(혼자 플레이일 때만, 씬 파일은 바뀌지 않음). 맵 구석을 시험할 때 걸어가지 않아도 된다.

### [ ] 에디터 환경설정 창과 단축키 도움말 (F1)
- 카메라 속도, 글자 크기·UI 배율, 자동 저장 간격, 외부 편집기 경로 등을 설정한다. `F1`로 단축키 목록.
- 레이아웃 파일(지금은 `mealkit_editor.ini` 하나를 모든 프로젝트가 공유)을 프로젝트별로 둘 수 있게 한다.

### [ ] 쿡북 문서

## 보류 / 넣지 않을 것

| 기능 | 결정 | 이유 | 다시 볼 조건 |
|---|---|---|---|
| Vulkan/OpenGL 등 다른 그래픽 API, RHI | 넣지 않음 | 절대 규칙 (DX12만) | - |
| 서버 권위형 넷코드 (스냅샷 보간, 예측) | 넣지 않음 | 락스텝이 물체 수와 무관하게 대역폭이 작다 | 수십 명 이상 장르를 만들 때 |
| 레이트레이싱, 디퍼드 렌더링, GI | 넣지 않음 | 내장 그래픽 예산을 넘는다 | - |
| 메시 셰이더 | 넣지 않음 | 최소 사양(Xe-LP)이 지원하지 않는다. GPU 주도 렌더링이 필요하면 ExecuteIndirect + 컴퓨트 컬링으로 | 최소 사양을 다시 올릴 때 |
| 롤백 넷코드 (GGPO 방식) | 보류 | 내 입력이 즉시 반응하지만, 틀릴 때마다 여러 틱을 다시 계산해야 해 물체 수천 개 게임에서는 예산을 넘는다. 대신 "내 캐릭터 겉모습만 예측"(1단계) | 물체가 적은 1:1 대전·격투 게임을 만들 때 |
| GPU 주도 렌더링 (GPU 컬링, ExecuteIndirect) | 보류 | 물체 수만 개에서 CPU 비용이 거의 0이 되지만 구현·디버깅이 어렵고, 수천 개 수준에서는 CPU 컬링이 충분하다 | 실제 게임에서 렌더링 준비 CPU 병목이 측정될 때 |
| Forward+ (광원 다수) | 보류 | 점광원 수백 개가 가능해지지만 내장 그래픽에서 컬링 패스 비용이 든다 | 밤 맵·실내처럼 광원이 많은 게임 |
| 고정소수점 게임플레이 수학 | 보류 | CPU·컴파일러와 무관한 결정론이지만, Jolt가 float라 두 체계가 섞이고 오버플로 버그가 새로 생긴다 | 다른 CPU 사이 디싱크가 실제로 발견될 때 |
| 스크립트 언어 (Lua 등) | 보류 | 즉시 수정·모딩이 되지만, 결정론 VM 개조가 필요하고 C++보다 수십 배 느리며 두 언어 디버깅. 0단계 핫 리로드 + 튜닝 데이터화가 효과 대부분을 가져간다 | 핫 리로드로도 부족하거나 모딩이 목표가 될 때 |
| 범용 ECS | 보류 | 객체 수만 개·유연한 조합에 유리하지만, 지금의 단순한 배열과 명시적 실행 순서(결정론 디버깅에 유리)를 잃는다 | 시스템 수·객체 수가 배열 구조로 감당 안 될 때 |
| 언리얼식 Actor 상속 계층 | 넣지 않음 | 빙의 구조만 가져오고(0단계 "플레이어와 캐릭터 분리") 상속 트리·가상 `Tick`은 쓰지 않는다. 실행 순서가 숨고 결정론 디버깅이 어려워진다 | - |
| 싱글톤·서비스 로케이터·DI 컨테이너 | 넣지 않음 | 엔진 기능은 인자(`GameContext&`, `World&`)로 받는다. 전역 상태는 그림자 시뮬레이션(World 두 개)과 핫 리로드를 깨뜨린다 (`docs/CODING_MODEL.md`) | - |
| 시뮬레이션 안의 코루틴·async | 넣지 않음 | 완료 시점이 PC마다 달라 디싱크가 나고, 코루틴 프레임은 해시·스냅샷할 수 없다. 틱 타이머와 `enum` 상태 머신을 쓴다 | - |
| 에디터 안 UI 디자이너 | 넣지 않음 | Penpot이 맡는다. 에디터는 미리보기 패널만 둔다 | - |
| Figma 연동 | 보류 | 클라우드 전용이고 REST API 호출 제한이 빡빡하다. `.ui`가 중간 형식이라 나중에 Figma 플러그인만 따로 만들 수 있다 | 디자이너가 Figma만 쓸 수 있을 때 |
| HTML/CSS·XAML UI 미들웨어, Rive | 넣지 않음 | 런타임이 크고 무겁다. 상태 전환(시간·이징)으로 기본 움직임은 된다 | 벡터 애니메이션이 게임의 핵심 연출일 때 Rive만 다시 본다 |
| UI 양방향 바인딩, 식 언어, 변환기 | 넣지 않음 | 단방향 뷰 모델 + 액션 하나로 정한다. 입력 위젯만 자기 필드에 쓴다 | - |
| UI 키프레임 애니메이션 (타임라인) | 보류 | 상태 전환으로 시작한다. Penpot 프로토타입 애니메이션은 가져오지 않는다 | 화면 연출 요구가 상태 전환으로 안 될 때 |
| UI 블러 효과 (레이어·배경) | 보류 | 내장 그래픽에서 비싸다. 플러그인이 경고한다 | 성능 예산에 여유가 확인될 때, 끌 수 있는 옵션으로 |
